The GUI smoke checks concurrent first launches, one process instance, search,
selection and scroll retention on refresh, confirmation blocking refresh, action
blocking polling, context argv received by the synthetic action helper, resizing,
native window close, no polling while hidden for longer than five seconds, and
reopening. It saves application-content captures only, using synthetic projects,
containers and PIDs. The temporary uninstalled app can log a portal registration
warning because its desktop entry is not installed; QML runtime warnings/errors
fail the smoke test. Screenshots in `docs/images` show this port, generated by this
test; the old upstream fixture `docs/demo-data.json` is retained as historical demo
data, and is not the smoke fixture.

Quickshell's IPC can return zero while reporting “Not ready to accept queries yet.”
The launcher therefore requires a literal typed `true` reply, and this case has a
regression test. Startup uses `flock` as well as `--no-duplicate` because the latter
alone checks for an existing process before startup and can race.

KWin initially configured this window below its requested minimum size. The app
now clamps the backing Qt window after configure events and preserves larger user
sizes. Both 840×620 and 1060×800 were exercised; details scroll at smaller sizes.
Programmatic minimization was not honored in this local session, so **title-bar
minimization, taskbar restoration and focus activation remain manual checks**.
The implementation gates polling on Quickshell's minimized state. The light test
forces only the app's color branch; it does not change the real KDE theme.

A read-only run of the actual backend successfully discovered projects and host
listeners. Docker's effective selected context was **desktop-linux**; its daemon
was unreachable, correctly yielding a Docker error and still showing host
listeners. Permission failures, timeouts, empty results, environment precedence,
context changes, and all disruptive operations were tested with mocks. No real
container or listening process was stopped, restarted, killed or removed.

No actual editor/AI session or Docker action was used as a runtime test. Those
integrations have argv/cwd regression coverage and still need laptop validation.
Qt clipboard behavior under actual focus is also a manual check; automated tests
do not overwrite the real desktop clipboard. Python 3.12 is configured in CI,
but only 3.14.7 was executed locally. CI itself has not been run remotely.

## Short laptop checklist

1. Install the verified dependencies and run `./install.sh`. Open the menu entry
   and both launcher modes. Launch twice; confirm one window. Close with Escape
   and the title bar, then reopen. Minimize/restore through the title bar/taskbar;
   check focus and keyboard navigation.
2. Set real project roots and `/usr/bin/fish` in config if needed. Use a project
   with spaces in its path. Check VS Code, Konsole's `pwd` and shell, Open workspace,
   Files, and copying a path into another app. Launch Codex and Claude interactively;
   configure a stable mise shim if KDE's PATH differs from fish's.
3. Resize, scroll the details, and search. Check the real KDE light and dark themes.
   In Services, select a row and scroll; wait through a refresh and confirm both
   remain stable. Leave a confirmation open and check that refresh pauses.
4. Start Docker Desktop yourself. Verify `docker context show` and the UI both show
   the intended target (normally `desktop-linux`). Compare `docker ps -a`, inspect
   and logs. Check that an unavailable daemon reports an error rather than no
   containers. A configured context must leave global `docker context show` unchanged.
5. If you choose to test disruptive controls, use only a disposable test container
   and a process you started inside a configured project. Check Cancel first,
   running-container removal prevention, stopped-container removal retaining
   volumes, and disabled controls for processes outside project roots. These
   checks are manual; the automated suite uses mocks exclusively.
6. Customize settings, rerun the installer, then uninstall without
   `--purge-config`; confirm the settings remain. Reinstall if desired. Manually
   add a KDE shortcut only after checking for a conflict.
